## Suggested starting hours

Run a two-week pilot with three 30-minute sessions each week, all in
**America/Phoenix (Arizona, Mountain Standard Time)**:

| Day | Time |
| --- | --- |
| Tuesday | 5:30–6:00 p.m. |
| Thursday | 5:30–6:00 p.m. |
| Saturday | 10:00–10:30 a.m. |

These are suggestions, not confirmed staffing commitments. Start Zoom five
minutes early. On Basic, the meeting clock applies to the entire office and
breakouts; later arrivals do not receive a fresh 40-minute window. Plan to finish
before the limit. Offer a scheduled follow-up for a longer application.

After two weeks, review visits, wait times, completed conversations, applications,
and missed visitors. Keep the strongest hours. If demand supports it, approve a
paid host license and expand to 60–90 minutes per session.

## One office, two roles

| Role | Job |
| --- | --- |
| Host / front desk | Start and end the meeting, monitor Waiting Room, greet visitors, assign private rooms, manage the queue. |
| Advisor / closer | Stay available in the meeting, take one household at a time, review options and next steps privately. |

On Basic, keep the host in the main room. Teammates join as participants and go
with visitors into host-assigned breakout rooms. The host manages admission and
room moves. Solo sessions require the host to check the Waiting Room between
conversations; do not promise immediate service. Paid co-host controls can support
front-desk backup. A co-host cannot start the meeting before the host; independent
coverage needs a separately verified alternative-host arrangement.

   Keep join-before-host off. Keep recording, AI summaries/transcripts, persistent

   Leave invitees empty; do not connect a calendar just to create the office link.
6. Review the draft and get operator approval before **Save** or account-setting
   changes. Do not purchase an upgrade without separate approval.
7. Copy **Invite Link / Join URL**, the participant link containing `/j/`.
   Never put a host start link, host key, `zak` token, or account credentials in
   page source or reports. Treat an approved participant URL as public-facing
   when used on the landing page; keep its passcode out of reports.
8. Test with a teammate: waiting-room admission, breakout assignment, return to
   lobby, screen share, and ending the meeting. Record success before traffic.

The office page opens Zoom in a new tab. It does not embed a meeting SDK, use the

## Host controls — quick reference

The account's **Breakout room – Meetings** setting is now enabled and verified
(October 12, 2026). Before the first session, confirm it remains enabled under
**Settings → Meeting → In Meeting (Advanced)**. Future account-setting changes
need operator approval. Start the desktop app as host.

| Action | Where / what to do |
| --- | --- |
| Admit | **Participants → Waiting Room → Admit**, one visitor/household at a time. |
| Create private rooms | **Breakout Rooms → Assign manually → Create**. Name them **Consultation 1**, **Consultation 2**, etc., without client names. |
| Place people | **Assign** the visitor and their advisor to the same room, then **Open All Rooms**. Disable room self-selection. |
| Move / return | In the breakout panel, use **Move To** for a selected visitor or advisor. Avoid **Close All Rooms** during another household’s conversation. |
| Help | Advisors/visitors use **Ask for Help** inside the room; the host can join. |
| Share | In the private room, share only the quote/application window. Confirm the intended visitor is the only household present. |
| Close | Stop new admissions, finish or schedule follow-ups, then **End Meeting for All**. |

Keep one unrelated household per room. Do not discuss health, banking, identity,
or application details in the main lobby, public chat, or another household’s
screen share. Screen sharing should explain the process; the advisor uses their
authenticated tools and the existing consent process.

## Standard visitor flow

1. **Welcome:** “Welcome to Evermore Life. I’m [name]. Are you here with a question,
   looking at coverage options, or working on an application?”
2. **Set expectations:** “We’ll connect you with an available teammate for a private
   conversation. If everyone is helping someone, we can arrange a callback.”
3. **Handoff:** host assigns one advisor and one household to a private room.
4. **Show and explain:** advisor confirms state/service availability, listens,
   shares appropriate quotes, and walks through next steps without promising
   eligibility, price, approval, or benefits.
5. **Record:** advisor records agreed follow-up through the authenticated
   [Inbound Client Intake Sheet](../../inbound-client-intake/index.html), using
   its existing consent and secure-storage flow. Do not ask visitors to use an
   internal team login or complete the advisor worksheet themselves.
6. **Finish:** close the conversation or book follow-up; advisor returns to the
   main room and tells the host they are available.
